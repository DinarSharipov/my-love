# ADR 0003: opt-in optimistic concurrency

- Статус: принято
- Дата: 2026-08-15

## Контекст

Партнёры могут одновременно редактировать общие записи. Обязательное новое поле
в request body сломало бы текущий generated frontend client, а сравнение только
по `updatedAt` зависит от точности и формата времени.

## Решение

- `FirstDate` и `FamilyEvent` получают целочисленный `version`, начинающийся с 1.
- Версия увеличивается при каждом изменении записи.
- `PATCH /first-date` и `PATCH /family-events/:id` принимают optional `If-Match`:
  число, `"число"` или weak ETag `W/"число"`.
- Если `If-Match` указан, update выполняется атомарным compare-and-swap внутри
  транзакции. Несовпадение возвращает `409` с code `VERSION_CONFLICT`.
- Если заголовок отсутствует, сохраняется прежнее last-write-wins поведение, но
  версия всё равно увеличивается. Это обеспечивает обратную совместимость и
  позволяет frontend включить защиту после регенерации клиента.

## Последствия

Новые поля ответов аддитивны. Текущий frontend продолжает работать без правок.
После поддержки `If-Match` frontend должен брать `version` из последнего GET или
mutation response и при конфликте предлагать обновить данные.
